# 관리자 권한 매트릭스

- 버전: 0.1v (초안)

- 참고 문서: [01_테이블정의서](./01_테이블정의서_0.1v_260914_11.42.md), [02_사용자구조및서비스방향성](./02_사용자구조및서비스방향성_0.1v_260914_11.42.md), [03_기능정의서](./03_기능정의서_0.1v_260914_11.42.md)
- 전제: `roles`는 ADMIN 하나만 사용. 등급 구분은 신규 role이 아니라 `users.org_id`가 가리키는 `org_units.org_type`으로 판단한다. **스키마 변경 없음** — 아래 스코프 규칙은 모두 애플리케이션(조회 쿼리의 WHERE 조건)로 구현한다.

## 1. 등급 정의

| 등급 | 판단 조건 | 데이터 접근 범위 |
|---|---|---|
| **최고관리자** (HQ ADMIN) | 로그인 사용자의 `users.org_id` → `org_units.org_type = 'HEADQUARTER'` | 전체 조직, 전체 테이블 데이터 |
| **지점장** (Branch ADMIN) | 로그인 사용자의 `users.org_id` → `org_units.org_type = 'BRANCH'` | 자기 `org_id` + `org_units.parent_org_id`로 연결된 하위 조직(STORE/WAREHOUSE)의 데이터 |
| (확장 후보) 매장/창고 담당자 | `org_type = 'STORE'` 또는 `'WAREHOUSE'` | 해당 매장/창고 단위만 (현재 시드 데이터엔 없음, 구조상 확장 가능) |

## 2. 스코프 판단 방식 3가지

테이블마다 조직 범위를 걸 수 있는 방식이 다릅니다.

- **직접(Direct)**: 테이블에 `org_id` 컬럼이 있어 바로 필터링 가능 (예: `inventories.org_id`)
- **간접(Indirect)**: FK를 한 단계 이상 따라가야 org를 알 수 있음 (예: `order_items` → `orders.org_id`)
- **전역(Global)**: 조직 개념이 없는 공통 자산 — 모든 관리자가 동일하게 보되, 쓰기 권한만 최고관리자로 제한 (예: `categories`, `roles`)

## 3. 도메인별 CRUD 매트릭스

표기: **C**=생성, **R**=조회, **U**=수정, **D**=삭제 / `-`=불가

### 3.1 사용자/조직

| 테이블 | 스코프 방식 | 최고관리자 | 지점장 |
|---|---|---|---|
| org_units | 직접(자기 자신) | C R U D (전체 조직) | R (자기 조직 + 하위만) |
| users | 직접(org_id) | C R U D (전체) | R U (자기 org 하위만, 상태변경 정도) |
| roles | 전역 | R (수정은 사실상 불필요 — 코드 고정) | R |
| user_roles | 간접(user_id→org_id) | C R U D | R (role 부여/회수는 최고관리자 전용 권장) |
| user_addresses | 간접(user_id→org_id) | R (CS 목적) | R (자기 org 소속 구매자만, CS 목적) |
| seller_profiles | 간접(user_id→org_id) *주1 | C R U D | R (자기 org 소속 판매자만) |

*주1: `seller_profiles`는 `org_id` 컬럼이 없고 `user_id`만 있음 — 판매자의 소속 org는 `users.org_id`(판매자 본인 계정의 org_id)로 판단.

### 3.2 상품/카테고리/재고

| 테이블 | 스코프 방식 | 최고관리자 | 지점장 |
|---|---|---|---|
| categories | 전역 | C R U D | R |
| products | 간접(seller_user_id→users.org_id) | C R U D (전체) | R U (자기 org 소속 셀러 상품만) |
| product_variants | 간접(product_id 경유) | C R U D | R U (상동) |
| product_images | 간접(product_id 경유) | C R U D | R U (상동) |
| product_files | 간접(product_id 경유) | C R U D | R U (상동) |
| inventories | 직접(org_id) | C R U D (전체) | C R U (자기 org만, 삭제는 최고관리자 전용 권장) |

### 3.3 주문/결제

| 테이블 | 스코프 방식 | 최고관리자 | 지점장 |
|---|---|---|---|
| orders | 직접(org_id) | R U (전체, 상태변경) | R U (자기 org만) |
| order_items | 간접(order_id→orders.org_id) | R U | R U (자기 org만) |
| payments | 간접(order_id 경유) | R (환불 승인 시 U) | R (자기 org 주문 건만) |

## 4. 화면 단위 권한 요약

| 관리 영역 | 최고관리자 전용 기능 | 지점장도 가능한 기능 |
|---|---|---|
| 조직 관리 | 조직 신설/수정/삭제 | 자기 조직 정보 조회 |
| 카테고리 | 카테고리 체계 관리 | 조회만 |
| 정책(이용약관/환불정책/AI설정) | 등록/버전관리/AI 프로바이더 설정 | 조회만 |
| 회원/역할 | 역할 부여, 회원 전체 조회, 강제 상태변경 | 자기 org 소속 회원 조회/상태변경 |
| 상품/재고/주문/문의 | 전체 범위 CRUD | 자기 org 범위 CRUD |

## 5. 구현 시 유의사항 (문서화 목적, 구현 아님)

- 위 매트릭스는 애플리케이션 레이어(백엔드 인증/인가 로직)에서 구현하는 것을 전제로 하며, DB 스키마 변경은 없음
- "간접" 스코프 테이블은 매번 JOIN으로 org_id를 판별해야 하므로, 실제 구현 시 조회 성능을 고려한 인덱스/쿼리 설계가 필요 (이번 문서 범위 밖)
- 지점장의 하위 조직 포함 여부(`org_units.parent_org_id` 재귀 탐색)는 현재 시드 데이터상 지사 아래 매장/창고가 없어 검증되지 않음 — 실제 매장/창고 데이터가 생기면 재귀 스코프 로직 검증 필요
